### and whether socio-economic structure adds predictive information

**Applied Data Science (83901), Bar-Ilan University — final project**

## 1. What the project asks

National COVID-19 averages hide large geographic variation. This project builds and
evaluates machine-learning models that **forecast local infection dynamics at the
level of individual statistical areas in Israel**, and tests whether a locality's
**static socio-economic / demographic structure** (2022 Census) adds predictive
value on top of its own recent epidemiological history.

**Initial questions**

1. Can we forecast local infection rates per statistical area with useful accuracy?
2. Do socio-economic features improve that forecast?
3. Which variables actually drive local infection trends?

**How the questions evolved.** Early framing aimed at hospitalisation / mortality
prediction; the local data proved too sparse for that and the target moved to
infection rate. The socio-economic question narrowed from "do these features help"
to "do they help *once recent local history is already in the model*" — and the
answer turned out to be essentially *no* for short-horizon forecasting, which
reshaped the story into baseline (cross-sectional, census) → improved model
(temporal, recent-history).

## 4. Method summary

### Data preparation (nb 01)
* COVID daily file → clean per-area daily panel: `'<15'` → 0, accumulated → daily
  diffs (negatives clipped), **adaptive infection rate** (widen the window backward
  until ≥ 30 tests), lockdown flag, per-area lag / rolling features.
* Census → `City_agas_code` key, synthesised whole-city rows, ≥ 90 % coverage rule for
  city aggregates, **70 raw columns → 27 features** (13 stand-alone + 7 domains ×
  [1 representative + 1 PCA index]).
* Two joins on `City_agas_code`: wave-2 targets × census (modelling table) and the full
  daily panel × census (EDA table). COVID sub-area codes vs 2022-census `StatArea`
  codes disagree for a sizeable minority of localities → kept as an explicit
  `has_census` flag, documented as a limitation.

### EDA (nb 02)
National vs local curves + whole-country weekly heat-map · within-city median/mean/IQR
· infection rate vs testing-volume bins · Spearman autocorrelation vs lag · **naive
persistence-forecast MAE by horizon (the baseline every model must beat)** · per-wave
Spearman(feature, burden) heat-map · vaccination QC & coverage · day-of-week effects.

### Basic model (nb 03) — cross-sectional, census → wave-2 outcome
110 models: 5 tracks (`mean_IR`, `peak_IR`, `slope_to_peak_IR`,
`severity_hosp_per_case` regression + `severity_present` classification) ×
(19 univariate + 3 combined). **GroupKFold by town** (leakage-safe),
**Ridge / L2-Logistic** (collinear features), **Benjamini–Hochberg FDR** on each
track's 19 p-values.

### Improved model (nb 04) — temporal, recent history → next-day infection rate
LSTM and XGBoost, same features / target / chronological 80/20 split, trained on
(A) the 3 largest cities separately and (B) all 1,397 statistical areas jointly.
Feature-importance for both families.

### Walk-forward validation (nb 05)
Expanding-window, 60-day initial train, **7-day horizon**, weekly step, retrain every
4 folds, identical fold dates for LSTM and XGBoost, 3-city and all-regions. Plus a
secondary hospitalisation-rate target.

## 5. Headline results (all from the committed result tables)

| model | scope | split | R² | MAE |
|-------|-------|-------|----|-----|
| Ridge (best) | census → wave-2 `mean_IR` | GroupKFold | **0.62** | — |
| L2-Logistic (best) | census → wave-2 `severity_present` | GroupKFold | AUC **0.77** | — |
| census → wave-2 `peak_IR` / `slope` / `severity` | — | GroupKFold | ≈ 0 | — |
| XGBoost | 3 cities | chrono 80/20 | 0.947 / 0.947 / 0.960 | ~0.012 |
| LSTM | 3 cities | chrono 80/20 | 0.78 / 0.80 / 0.87 | ~0.026 |
| XGBoost | all 1,397 areas | chrono 80/20 | **0.954** | 0.017 |
| LSTM | all 1,397 areas | chrono 80/20 | 0.851 | 0.031 |
| **XGBoost** | all 1,397 areas | **walk-forward** (1,325,217 preds) | **0.946** | 0.013 |
| persistence baseline | — | — | — | ≈ 0.03–0.06 |

**Answers.** (1) Local infection-rate forecasting is feasible — walk-forward
R² ≈ 0.95, beating persistence. (2) Socio-economic structure does **not** improve
short-horizon forecasting once recent local history is in the model (and its
association with burden flips sign across waves). (3) The signal is
`infection_rate` rolling-3 + lag-1; `hosp_daily` ≈ 0.

**Key limitation.** Error rises on every wave up-swing — the model lags at turning
points and under-predicts peaks, which is exactly where a surge-warning use-case
needs it most. This is the priority for future work (multi-step horizon, change-point
features, mobility data).
